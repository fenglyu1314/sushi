## Context

M1 已跑通经济闭环，但生产是「决策阶段即时出成品 + 全屏文字 UI」，与 GDD §5.4 设计的「现做 → 出餐台 → 摆货架 → 卖空补货」核心手感差距明显。本轮在**不引入场景演出层、不做冰箱格子化**的前提下，把生产链重做为「单线程制作队列 + 出餐台 + 货架」的功能白盒。

现状约束：
- 现有 `run_state.gd` 用单一「当日成品池」（`finished_sushi`）承载成品，sales 直接从中扣减。
- `Recipe` 无制作时长字段；生产为即时。
- 时间模型：决策阶段（无 tick） → 营业/模拟阶段（tick 推进 sales） → 结算。
- 引擎约定：AI 不直接改 `.tscn/.tres`，配方 `craft_time` 的数值填写由人在编辑器内完成。

## Goals / Non-Goals

**Goals:**
- 备货阶段生产**即时完成**（无耗时/进度条/队列），营业阶段制作需时间（单线程队列自动逐个，进度条），成品落**出餐台**。
- 备货阶段可对已产成品**取消退料**（返还该份全部食材，决策可逆）；**开摊 = 不可逆提交点**，营业阶段不可退料。
- 出餐台容量上限（初始 4）：营业阶段满则暂停制作、出空位恢复；备货阶段满则拒绝生产。容量升级留接口。
- 货架 N×N，成品**每款占 1 格**，玩家从出餐台**拖放**成品上架。
- 出餐台 / 货架成品可拖到**垃圾桶作废**（营业阶段作废 = 沉没成本；备货阶段等同取消退料）。
- sales 只卖**货架上**的成品；卖空 → 玩家从出餐台补货。
- 采购仅限备货阶段。
- 全程白盒（纯色块 + 文字 + 进度条），交互集中在下方操作面板。

**Non-Goals:**
- 上方场景演出层（餐车 / 道路 / 顾客走动）。
- 冰箱格子化（主料占格）——沿用现有数值食材库存。
- 出餐台容量升级的实装 UI（仅留接口）。
- 顾客排队 / 前排取货位 / 犹豫窗口 / 现做以外的多线程产能。
- 成品新鲜度 / 过期（本轮成品不过期）。

## Decisions

### D1. 时间模型：备货即时、营业计时
制作时间**只存在于营业阶段**，两阶段生产模型不同：
- **备货阶段**：点「生产」瞬间出成品，**无耗时、无进度条、无队列**；受出餐台容量约束（满则产不了）。
- **营业阶段**：制作需时间，按真实秒累加推进单份进度，单线程队列逐个自动制作，出餐台满则暂停。
- **理由**：备货是"摆盘规划"，即时反馈才顺手；营业才需要"边卖边做"的实时张力，进度条 / 满暂停都落在这一阶段。
- **备选**：贯穿两阶段计时（否决，备货即时更顺手，已由用户更正）；纯回合制无耗时（否决，营业阶段正是要引入的手感）。

#### D1.1 制作时钟的驱动方式（run_state 保持纯数据）
`run_state` 是 `RefCounted`（不挂场景树，便于命令行验证与存档），**不能也不应**依赖 `_process(delta)` 自行计时。制作计时按「纯数据推进方法 + 外部 Node 驱动」拆分：
- **`run_state` 暴露 `advance_crafting(delta: float)`**：只负责"推进 delta 秒后当前制作项进度如何变化"——累加进度、完成则扣料落台、出餐台满则冻结落台、取队列下一项。此方法纯逻辑、无引擎依赖，测试可手动喂步长步进。
- **由 `day_cycle`（已是 Autoload Node、全局时间权威）驱动**：仅在 `Phase.SIMULATION` 期间，每帧 `_process(delta)` 调用一次 `run_state.advance_crafting(delta)`。备货 / 结算阶段不调用。
- **理由**：保持 `run_state` 纯数据可测；`day_cycle` 本就是唯一时间权威，制作时钟与 sales tick 同源管理，未来接 `time_scale`（加速 / 暂停）只需改一处。
- **备选**：`run_state` 自身 `_process`（否决，`RefCounted` 无此回调、且会破坏"不挂树"约定）；另立 `production_controller` Node（否决，与 `day_cycle` 的时间职责重复，徒增一个节点）。

#### D1.2 单一时间时钟：一天按真实秒推进，tick 只是售卖采样粒度
营业阶段由 `day_cycle._process(delta)` 单一时间时钟统一驱动，避免"Timer 跑 tick + _process 跑制作"两套时钟错位：
- **一天时长可调**：`DAY_DURATION_SEC`（默认 90s）为核心手感参数——旧方案 `8 tick × 0.5s = 4s` 一天太短、单份制作 4s 都做不完，"还没反应过来就结束"。现按真实秒累计，到 `DAY_DURATION_SEC` 进入结算。
- **制作按真实秒**：每帧 `advance_crafting(delta)` 推进当前制作项。
- **sales 按 tick 采样**：`TICKS_PER_DAY`（默认 20）仅作为把全天人流量均摊的采样粒度；`_day_elapsed` 每跨过 `TICK_INTERVAL = DAY_DURATION_SEC / TICKS_PER_DAY` 秒即 `tick_advanced.emit`，由 `game_session` 触发 `sales.process_tick`。
- **同起同停**：`_process` 以 `Phase == SIMULATION` 为唯一守卫，制作与 sales 采样天然同源、同起同停；离开该阶段两者一并停止。
- **UI 倒计时**：`day_cycle` 暴露 `get_day_remaining()/get_day_progress()`，营业面板每帧显示"营业剩余 XX / YY 秒"，比离散 tick 更直观。
- 若后续引入「加速 / 暂停」，只需对这一处 `delta` 施加 `time_scale`（本轮不做加速）。

### D2. 单线程制作队列（营业阶段）
队列机制**仅营业阶段生效**：同一时刻只制作 1 款；队列为有序列表，队首完成 → 出成品 → 取下一个。
- 入队：营业阶段玩家在生产面板点某配方「加入队列」，可重复入队叠加数量。
- 备货阶段无队列——点「生产」即时得一份（相当于零耗时的单次制作）。
- 扣料时机：营业阶段在出成品的**瞬间**扣料；备货阶段在生产的瞬间扣料（即时，故等同瞬间）。食材不足则该项**跳过并给出提示**，不阻塞后续可做项。
- **理由**：单线程贴合 GDD「单人摊主」设定，也让营业期「做什么 / 做多少」成为核心决策；瞬间扣料避免入队即锁料导致的僵局。
- **备选**：入队即扣料（否决，排长队后无法灵活调整）；多线程并行（否决，属后续里程碑产能升级）。

### D3. 出餐台（原缓冲区）容量与暂停
出餐台是**有序成品列表**，容量 `buffer_capacity`（初始 4，留 `upgrade` 接口），两阶段共用同一容量约束，但满时行为不同：
- **营业阶段**：一份完成时出餐台已满 → **制作暂停**（进度可到 100% 但成品悬停 = 冻结落台），出现空位后自动落台并继续。
- **备货阶段**：即时生产，出餐台满则**直接拒绝生产**（无"暂停/恢复"概念，因无持续制作过程），须先上架或取消退料腾出空位。
- **理由**：满则受阻是玩家「必须及时摆货架 / 止损」的压力来源，正是本轮要验证的手感。
- **实现取舍**：营业暂停选**冻结落台**（进度可到 100% 但成品悬停，出空位即落），实现更简单且语义清晰。

### D4. 货架：N×N，每款占 1 格
货架为 `N×N` 格网格（建议 `N=3`），每格放 1 份成品，**任何款式都占 1 格**（本轮统一，多格 footprint 留后续）。
- 上架：从出餐台拖 1 份到空格 → 出餐台移除该份、货架该格填入。
- **理由**：先统一 1 格验证拖放与容量手感；`Recipe.shelf_slots` 字段暂不启用空间约束（保留字段，本轮忽略其值）。

### D5. sales 取货源改为「仅货架」
sales 成交时从**货架**移除 1 份匹配款式；货架无该款 → 流失（与现有语义一致，仍不扣钱不耗料）。
- 出餐台里的成品**不参与售卖**，必须先上架。
- **理由**：这是方案 B 的核心——营业中「卖空货架 → 从出餐台补货」的临场循环。
- **数据结构**：`run_state` 的单一 `finished_sushi` 池拆为 `buffer`（出餐台）与 `shelf`（货架）两个结构；sales 只读 `shelf`。

### D6. 拖放契约（合法转移矩阵）
| 源 \ 目标 | 货架空格 | 垃圾桶 | 其他 |
|---|---|---|---|
| 出餐台成品 | ✅ 上架（占 1 格） | ✅ 备货=取消退料 / 营业=作废 | ❌ |
| 货架成品 | ❌（本轮不支持架内挪动 / 下架回台） | ✅ 备货=取消退料 / 营业=作废 | ❌ |
- 非法放置：回弹到源位置，无状态变化，给白盒提示。
- 货架满时拖向货架：视为非法，回弹。
- **拖向垃圾桶按阶段分流**：备货阶段 = 取消退料（`return_ingredients`，返还食材、不记沉没成本）；营业阶段 = 作废（`record_waste`，沉没成本），成品消失。

### D9. 备货生产可逆：即时生产 + 取消退料，开摊为提交点
备货阶段的生产决策**完全可逆**，开摊那一刻起冻结为不可逆。
- **即时生产**：点「生产」→ 瞬间扣料并出成品落出餐台（受容量约束，满则拒绝）。
- **取消退料**：对备货期出餐台 / 货架上的成品执行取消 → **返还该份全部食材**（主料 + 辅料按每份消耗量原额返还），成品消失，**不记沉没成本**。
- **提交点 = 开摊**：进入营业阶段后，所有在手成品（出餐台 + 货架）不可再退料；此后未卖出只能作废（沉没成本），结算时剩余一律作废（见 D8）。
- **理由**：备货是可反复试的"规划期"，允许退料让玩家敢多备；开摊即承担风险，把"实亏"压力集中到营业与结算，让两阶段手感自然分层。
- **UI 复用**：备货与营业都用同一个垃圾桶拖放目标，语义按阶段自动切换（退料 / 作废），无需两套控件。

### D7. 数据模型：`Recipe.craft_time`
`Recipe` 新增 `@export var craft_time: float = 4.0`（秒，制作单份耗时）。**仅营业阶段生效**；备货阶段即时生产忽略该值。
- 数值本轮建议（人在编辑器内填 `.tres`）：卷类 ~4s、握寿司 ~3s、刺身 ~6s；先给全部默认 4s 亦可。
- 事件总线新增信号（供 UI 订阅）：`craft_started(recipe_id)`、`craft_progress(recipe_id, ratio)`、`craft_finished(recipe_id)`、`crafting_paused` / `crafting_resumed`、`buffer_changed`、`shelf_changed`、`sushi_wasted(recipe_id, source)`、`ingredients_returned(recipe_id)`。

### D8. 结算作废：出餐台 / 货架剩余成品一律作废
营业阶段结束进入结算时，出餐台与货架上**所有未卖出的成品 MUST 一律作废**，各记一次沉没成本（`record_waste`），出餐台与货架清空。
- **理由**：本轮成品无新鲜度 / 不跨回合留存，"没卖出 = 实亏食材成本"给玩家"备货不能过量"的核心压力，与「流失 vs 浪费」语义一致。
- **与拖放作废的区别**：拖放作废是玩家主动止损，结算作废是系统在回合末的批量清算；两者都走 `record_waste`。

### 建议数值汇总（可调）
| 项 | 建议值 | 说明 |
|---|---|---|
| 货架 N | 3（3×3=9 格）| 白盒先验证 |
| 出餐台容量 | 4 | 已定，留升级接口 |
| `craft_time` | 3~6s / 款 | 数据驱动，默认 4s |

## Risks / Trade-offs

- **[备货即时生产可能让玩家过量囤货]** 备货可退料，玩家可能无脑多产 → 缓解：出餐台容量 + 货架格数天然限制在手量；开摊即冻结、未卖作废（沉没成本）反向约束囤货冲动。
- **[退料 / 作废按阶段分流易混淆]** 同一垃圾桶在备货是退料、营业是作废，玩家可能误判 → 缓解：拖到垃圾桶时按阶段给明确白盒提示（「已退还食材」/「已作废，成本沉没」）。
- **[run_state 结构变更破坏存档]** `finished_sushi` 拆为 `buffer`/`shelf` → 缓解：M1 白盒阶段接受存档重置，save-system 做兼容或直接失效旧档。
- **[实时计时与营业 tick 双节奏易混乱]** → 缓解：本轮不做加速 / 暂停，两套节奏各自独立；未来引入 `time_scale` 时统一。
- **[单线程 + 满暂停可能让玩家「无事可做」空等]** → 缓解：正是要测的张力点；若手感差，下一轮再调容量 / 耗时或引入多线程升级。
- **[拖放白盒手感]** Godot Control 拖放（`_get_drag_data`/`_can_drop_data`/`_drop_data`）在纯色块上需要清晰的高亮 / 回弹反馈 → 缓解：tasks 里单列拖放反馈项。

## GDD §5.4 对齐说明（任务 6.2）

本轮白盒实现与 GDD §5.4「现做 → 缓冲区（正式术语=出餐台）→ 手动摆货架 → 卖空补货」核心循环一致：制作单线程可排队、做好先进出餐台、出餐台有限堆满则阻塞、须手动摆上货架、sales 只卖货架成品。以下为**有意简化 / 口径细化**，均属本轮白盒范围裁剪，不改变 GDD 大方向：

- **成品占格统一为 1 格**：GDD §5.2/§5.4 设想「成品按形状占货架格（小卷 1 / 握寿司 2 / 刺身 2×2）」；本轮统一「每款占 1 格」先验证拖放与容量手感，`Recipe.shelf_slots` 仅保留字段、不施加空间约束（见 D4），多格 footprint 留后续 change。
- **计时只落在营业阶段**：GDD §5.4 以营业循环描述「点击制作→自动计时」；本轮明确「备货即时、营业计时」两段式（见 D1），备货为零耗时即时生产、可取消退料，开摊为不可逆提交点——是对 GDD 循环的阶段化细化，非偏离。
- **未纳入本轮**（Non-goals 已列）：GDD §5.5 前排取货位 / 等待队列 / 犹豫窗口、上方场景演出层、冰箱格子化、成品新鲜度——均另立 change。
- **术语**：GDD §5.4 行文中的「缓冲区」以术语表为准正式改称「出餐台」（见 `docs/00-术语表.md`，已弃用「缓冲区」）。
