## ADDED Requirements

### Requirement: 会话初始化与日循环编排

系统 SHALL 提供会话编排层，持有运行状态、内容集、当前地点与随机源，并协调日周期各阶段调用对应系统逻辑，形成可连续游玩的多天循环。

#### Scenario: 开始一局会话

- **WHEN** 会话初始化
- **THEN** 建立初始现金的运行状态、载入内容集与当前地点
- **AND** 通过日周期进入第一天的决策阶段

#### Scenario: 模拟阶段按 tick 推进售卖

- **WHEN** 处于模拟阶段且日周期推进一个 tick
- **THEN** 会话调用售卖逻辑处理该 tick 的顾客到达与成交/流失

#### Scenario: 结算阶段触发日结算

- **WHEN** 进入结算阶段
- **THEN** 会话调用结算逻辑对当前运行状态与地点结算
- **AND** 复盘数据经事件总线广播供 UI 呈现

#### Scenario: 进入下一天

- **WHEN** 玩家在结算后请求进入下一天
- **THEN** 现金与结转库存保留、当日统计重置，进入新一天的决策阶段

### Requirement: 向 UI 暴露玩家动作

会话 SHALL 向 UI 暴露采购、生产、开摊、进入下一天等玩家动作，并回传结果供 UI 反馈；动作 MUST 复用既有系统逻辑，保持阶段与现金约束一致。

#### Scenario: 请求采购

- **WHEN** UI 在决策阶段请求采购某食材若干单位
- **THEN** 会话调用采购逻辑，成功则扣现金入库存并返回成功，现金不足或非决策阶段返回失败且状态不变

#### Scenario: 请求生产

- **WHEN** UI 在决策阶段请求生产某配方若干份
- **THEN** 会话调用生产逻辑并返回实际生产份数（可能因库存/辅料上限少于请求值）

#### Scenario: 请求开摊

- **WHEN** UI 在决策阶段请求开摊
- **THEN** 会话令日周期从决策阶段进入模拟阶段

### Requirement: 向 UI 暴露只读状态查询

会话 SHALL 提供只读查询：当前现金、指定食材库存、指定配方的最大可做份数、指定配方的当前成品份数，供各 UI 面板展示与按钮可用性判断。

#### Scenario: 查询配方最大可做份数

- **WHEN** UI 查询某配方在当前库存下的最大可做份数
- **THEN** 返回按所有所需食材共同约束、向下取整的份数

#### Scenario: 查询现金与库存

- **WHEN** UI 查询当前现金或某食材库存
- **THEN** 返回运行状态中的对应数值
