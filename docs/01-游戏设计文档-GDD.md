## 1. 核心定位

**一个关于「预测需求、对抗浪费」的寿司日料经营模拟游戏。**

玩家从中国城市街头摆摊卖一元寿司起步，逐步经营成拥有回转传送带、独立座位、多品类厨房的餐厅。核心乐趣在于：**在信息不完全的情况下预判顾客喜好，精准采购与生产，最大化利润、最小化浪费**。

## 2. 差异化 / 核心 Hook

- 与《胡闹厨房》《潜水员戴夫》等**操作向**餐厅游戏不同，本作是**决策/规划向**。
- 核心 Hook：**浪费经济**——做多了卖不掉就得倒掉（亏钱），食材会过期，传送带空间会被占用。玩家对抗的不是手速，而是「不确定性」。

## 3. 核心玩法循环（贯穿全程）

```
预测需求 ──▶ 采购食材 ──▶ 生产菜品 ──▶ 售卖 ──▶ 结算/止损
(地点+喜好)  (成本/保质期)  (产能约束)   (卖不掉)  (倒掉=亏钱)
   ▲                                                │
   └──────────────── 复盘、调整下一轮 ◀──────────────┘
```

**设计原则**：每个新阶段不是替换玩法，而是在同一循环上**叠加新的约束层**。

## 4. 阶段进程（概览）

> 本节只做宏观概览。摆摊阶段详见 §5，开店（传送带）阶段详见 §6。

| 阶段 | 形态 | 新增机制/约束 | 核心张力 | 定位 |
|------|------|--------------|---------|------|
| ① | 街头摆摊(一元寿司) | 采购、生产、卖不掉倒掉 | 生产量 vs 需求 | 新手教学 |
| ② | 小店 + 回转传送带 | 传送带占位、食材保质期、**寿司新鲜度(转圈)**、随机事件；客单价↑但顾客要求↑ | 空间占用 vs 备货、新鲜 vs 浪费 | 核心中期 |
| ③ | 扩张 + 自动化 | 厨师(自动生产+自动上盘+按新鲜度阈值自动丢弃)、独立座位(点单制/零浪费)、服务员(送餐产能) | 浪费流 vs 精准流 | 成长期 |
| ④ | 多品类厨房 | 拉面、烧烤等新产线 | 品类广度 vs 管理复杂度 | 深度扩展 |
| ⑤ | 布局优化 | 店铺扩大后自由摆放桌椅/传送带/厨房，提升吞吐效率 | 摆放策略 vs 效率 | 高玩/长线 |

### 4.1 各阶段机制速览

- **街头摆摊（①）**：地点决定顾客构成与喜好；每轮开始前决策买什么食材、做哪些寿司；结束后未售出的寿司作废（亏钱）。
- **回转传送带（②）**：容量有限，无人吃的寿司持续占位 → 无法放新品 → 需预判喜好 + 提前备货；食材耗尽则无法制作，食材过期作废。
- **随机事件（②起）**：某食材涨价/降价；某事件导致顾客临时忌口某食材。
- **独立座位（③）**：顾客点单后才制作 → 几乎不浪费，但需要服务员把成品送达（服务员是产能瓶颈）。
- **布局（⑤）**：店铺扩大后解锁——在网格上自由摆放桌椅、传送带路径、厨房位置；不同摆法影响顾客流、送餐距离、传送带吞吐，借此优化整店效率。

### 4.2 进程主线与开店门槛

```
摆摊(起点/教学) ──▶ 开店 ──▶ 把单店做到「全功能解锁」(终极目标)
```

- **终极目标 = 单店全功能解锁**（已确认，不做连锁）：把一家店做到十全十美即为「圆满/通关态」，而非无限滚数值。逐步解锁：更长传送带、更多座位、更大厨房、更多寿司师傅、后期热食产线(拉面/烧烤)、包间等（对应阶段 ③④⑤）。
- **通关判定 = 成就 + 任务全收集（软通关，可续玩）**（已确认）：不设硬性结束条件——游戏内置**成就系统**与**任务系统**，两者**全部达成/收集**即视为「通关/圆满」并给予认可；但通关后玩家**仍可无限继续经营**（沙盒续玩），不强制结束。
- **开店门槛**：从摆摊进入开店须**同时满足**——① **商业街好感度 ≥ 60%**（商业街为最高阶地点，见 §7.2）；② **资金达到开店最低要求**。好感度门槛让「先摸熟地段、再扎根开店」成为硬性前提，与好感/情报系统(§7.3-7.4)天然咬合；资金门槛则是风险闸门。
- **各地点好感度 → 合并为开店初始好感度**：**地点好感度仅用于摆摊阶段**；开店后不再分地点计算，而是把**各地点已积累的好感度按一定比例合并**为一个店铺好感度，作为开店起点，此后店铺好感度独立运营（见 §6.6）。
- ❓待定：各地点好感度合并为店铺好感度的**比例系数**；开店期破产是否回退摆摊、以及回退时的好感度折算方式。

## 5. 街头摆摊阶段 · 详细设计（已确认）

> 这是 M1 要验证的核心闭环。规则已讨论确认，具体数值待原型中调优（标 🔴）。

### 5.1 回合结构：混合制（开摊前决策为主 + 营业中补货）

- **一个回合**通常对应「一天」（后续如「夜市街」等地点可能只占一天中的部分时段，故以「回合」为准）。**开摊前**做主要决策，**营业中**做有限执行（现做补货）。
- **开摊前**制作寿司：即时完成，**无制作时间**。
- **开摊后**：食材**不可补充**，只能消耗库存；现做寿司**需要时间**，不同寿司耗时不同。

### 5.2 两层空间约束

```
主料 (鱼/贝/蛋…)   → 冰箱格子 pack   (仅开摊前博弈「带哪些/带几条」)
辅料 (米饭/紫菜/醋) → 独立容器+数值上限 (如米饭100单位，可升级扩容)
成品寿司            → 货架格子 pack   (营业中摆放)
```

- **主料 · 冰箱格子 pack**：主料按形状占格（如三文鱼 1×3、青瓜 1×1、比目鱼 2×2，数值待调）；pack 得越巧 = 能带的主料越多 = 当日产能上限越高。因开摊后不再补料，冰箱格子**只在开摊前**博弈。
- **辅料 · 独立容器**：米饭/紫菜/醋等，不占格子，用数值上限管理（如米饭初始 100 单位）；可升级（电饭煲等）提升上限 = 成长钩子 + 软产能天花板。
- **成品 · 货架格子 pack**：寿司按形状占货架格（小卷 1、握寿司 2、刺身 2×2，数值待调）；占格越大者单价/利润越高 → 「少而精 vs 多而廉」策略光谱。
- 假设（可再确认）：格子形状**先用矩形**，异形（俄罗斯方块式）留作后期高级食材/寿司；货架直接用格子，暂不保留独立「盘子」计数概念。

### 5.3 食材 → 寿司 转化模型

- 食材有**「原料总量」**，配方定义**「每份消耗量」**，系统自动算份数（一种食材支持多种用途，扩展不改份数表）。
- 示例（一条三文鱼）：

  | 配方 | 可做份数 | 成品占货架 | 定位 |
  |------|---------|-----------|------|
  | 三文鱼小卷 | 40 | 1 格 | 走量薄利 |
  | 三文鱼握寿司 | 20 | 2 格 | 中庸 |
  | 三文鱼刺身 | 5 | 2×2 格 | 少而精、高价 |

- 规律：加工越精 → 份数越少、占货架越大、单价越高。想做更多某款 → 带第二条（占更多冰箱格）。

### 5.4 营业阶段循环

```
顾客到达，头顶显示「具体想要的寿司图标」
   ├─ 货架上有 ─▶ 自取 + 扫码结账 ✅ (赚钱)
   └─ 货架上没有 ─▶ 离开 ❌ (流失=少赚) ，但头顶图标=需求情报
                    │
        看情报 ─▶ 点击制作(自动计时,单线程可排队) ─▶ 做好进缓冲区 ─▶ 手动摆到货架格子
```

- 缓冲区**有限**：堆满则阻塞后续制作 → 逼玩家及时把成品摆上货架（轻度临场压力）。

### 5.5 两类「亏」（痛感区分）

- **流失**：顾客没买就走 = 机会成本，「少赚」，**不直接扣钱**。
- **浪费**：做多卖不掉 / 食材过期 = **实亏**，收摊结算时倒掉扣钱。
- 效果：玩家怕「做太多」胜过怕「流失」，决策更真实。

### 5.6 渐进解锁（保教学友好）

- 初期：冰箱/货架格子小、食材规整小块、寿司种类少。
- 随进程解锁：更大格子空间、异形大寿司、更多品类、辅料容器升级。

### 5.7 待调数值 ❓

- 各主料占格形状与原料总量；各配方每份消耗量、成品占格、售价。
- 缓冲区容量、各寿司制作耗时。
- 米饭等辅料初始上限与升级曲线。

## 6. 开店阶段（回转传送带）· 详细设计（进行中）

> 对应阶段 ②，在摆摊循环（§5）上叠加三层新约束：**传送带占位、寿司新鲜度(保质期)、更高的顾客要求**。

### 6.1 回转传送带 = 占位 + 新鲜度（已确认核心）

- **占位**：传送带格子有限，没人拿的寿司一直占位绕圈 → 占满就放不了新品 → 逼玩家「别乱做」；把摆摊阶段静态货架的占位升级为动态循环。
- **新鲜度(保质期) = 盘上进度条**（已确认）：每盘寿司带一条**新鲜度进度条**，随转圈递减，玩家一眼可判。**进度条不影响顾客是否拿取**（顾客只认喜好，见 §6.4），它只决定「被吃后好感度如何变化」（见 §6.6）、并提示玩家该及时撤盘。
- **盘子与寿司一体 = 占位随取用释放**（已确认）：盘子跟着寿司走——**顾客把寿司吃掉时，盘子随之撤出传送带、该格子立刻空出**，玩家（初期手动 / 后期员工）再把下一盘寿司补位。也就是说「占位」只在**寿司还没被吃**时成立：
  - **被吃走** → 盘随寿司离带，格子自动腾空（正常周转）。
  - **没被吃 + 变质**（进度条见底）→ 盘子**不会自动消失**，仍占位绕圈，须玩家/员工**撤下作废（实亏）**；期间若被喜欢它的顾客拿走照吃，会**送客进医院**（见 §6.4）。
- 「做多了」的代价当着玩家面一圈圈转，比货架直观，也把保质期实体化为看得见的进度条。

### 6.2 食材采购：随时补货 + 货仓容量上限（已确认）

与摆摊阶段「开摊后不可补料」（§5.1）相反，**开店后食材可随时补货**——供给端从「开局一锤定音」变成「全程动态运营」。但采购受**货仓容量上限**约束：

- **货仓 = 单一总容量池**（已确认）：所有食材共用**一个总容量数值**，不分食材、不做占格博弈（开店阶段玩家注意力应放在传送带/翻台，采购力求简单，初期不叠俄罗斯方块）；容量可随进程升级扩容（成长钩子）。
- **仓满 = 无法继续补货**：进货过量把货仓塞满后，补货被卡住 → 逼玩家别盲目囤料。
- **两条泄压手段**：仓满/囤压时可 ① **降价促销**——把过剩食材加紧做成寿司低价卖掉，回收部分成本；② **直接扔掉**——腾仓但**实亏**。

### 6.3 食材保质期：临期提醒 → 过期作废扣钱（已确认）

开店后食材**会过期**（摆摊阶段食材不过期，见 §9.1）——这是开店阶段解锁的「时间层」约束。

- **临期提醒**：食材接近保质期时给玩家**明确可视提醒**，提示「赶紧做成寿司卖掉/促销清库存」，把过期止损做成可操作窗口，而非闷声扣钱。
- **过期 = 自动作废扣钱（实亏）**：到期未用的食材自动清除并结算亏损，与成品「做多了变质」同为实亏。
- **与货仓叠成「囤货双亏」**：货仓卡**空间**、保质期卡**时间**——囤太多既占仓又会过期，把「多囤=更稳」的直觉反过来变成风险，与成品端「做多了占位/变质」（§6.1）同构，供给-成品两端风险对称。促销/清库存正是两条约束的共同泄压阀。

### 6.4 顾客取用逻辑 = 沿用摆摊喜好模型（已确认）

- **升维：客单价↑，顾客要求↑**（已确认方向）：开店后寿司**单价提高**（支撑更高成本），但顾客**要求同步提高**——尤其**对新鲜度敏感**：转久了、不够新鲜的寿司顾客不愿拿 → 逼玩家精准备货、及时撤旧。价高与要求高互相制衡，防止「涨价躺赢」。
- **取用规则（统一，不区分普通/粉丝）**：所有顾客头顶显示**自己喜欢的寿司**；该寿司在传送带上经过其面前时就**拿下来吃**——**只认喜好、不看新鲜度**。新鲜度不决定「拿不拿」，只决定「吃完后好感度如何变」（见 §6.6）。
- **核心压力**：某款寿司若没被及时吃掉又没撤，变质后**仍会被喜欢它的顾客拿走** → 送医、好感度暴跌 → 「及时撤旧」是**避免出人命的硬压力**，而非可选优化。

### 6.5 顾客行为：坐下吃多盘 + 翻台率（已确认）

开店后顾客不再「路过即走」，而是**入座、持续从传送带取多盘、停留一段时间**。由此引入**翻台率**——座位有限，一桌吃得慢则后来者**排队/流失**；玩家的备货预判直接决定「这一桌吃几盘、贡献多少客单」。后期需**服务员**岗位（引导入座/收盘/加速翻台），是继厨师之后的第二条自动化线（阶段 ③）。

### 6.6 新鲜度 × 好感度 = 分级结算

此处的好感度 = 本店的店铺好感度，暂不做每个顾客独立好感度。同一款寿司被吃时越不新鲜，回报越差：

- **新鲜**：好感度**加更多**（正反馈）。
- **不太新鲜**：好感度只**加一点**。
- **更不新鲜**：不加、甚至**倒扣**好感度。
- **完全不新鲜(变质)被吃**：顾客可能**进医院** → 好感度**大幅暴跌**（最重惩罚）。

**好感度 → 回头客**：店铺好感度越高，**回头客越多**（重复到店的顾客占比越高）→ 稳定的客源与客单，是「把店做好」的核心正反馈。

### 6.7 生产与上盘：手动教学 → 雇员自动化（已确认，循序渐进）

- **开店初期（仅老板）**：沿用摆摊手感——玩家选寿司种类/数量、自动生产，再**手动把成品放上传送带**、**手动扔掉转过期的寿司**。亲手放盘/丢弃，把「占位」和「新鲜度」两个新机制**用手教一遍**，痛感最直接。
- **规模变大后（招员工）**：员工按玩家指定的配方/数量**自动生产并上盘**，并按玩家设定的**新鲜度阈值自动丢弃**过期寿司。手动操作 → 升级为「设定策略参数」，从操作向平滑过渡回**决策/指挥向**（呼应 §2 定位、对应阶段 ③ 自动化）。
- **经济闭环**：初期手动量随规模上升 → 忙不过来 → **花钱买自动化(招人)** 解压 → 形成经济驱动的成长曲线。

### 6.8 打包 / 外卖订单（后期逐渐加入）❓

堂食之外的需求出口——可消化传送带上「快过期但还没坏」的库存、拓宽客源；作为后期内容分批引入，不进入开店首版。

### 6.9 待调数值 ❓

- 传送带格子数/单圈时长、进度条清空对应的转圈数、寿司保质圈数。
- 各新鲜度区间的好感增减分界与幅度、「进医院」触发概率与暴跌幅度。
- 员工数量/人力成本曲线；座位数、翻台与排队的结算规则；是否按盘色定价。
- 货仓总容量与升级曲线、各食材占仓量、食材保质时长与临期提醒提前量、促销折扣与回收率。

## 7. 地点 · 顾客 · 好感 · 情报 · 事件（已确认）

> 这是「预测需求」这半边玩法的核心，与 §5 摆摊循环直接咬合。规则已讨论确认，数值待原型调优（标 🔴）。

### 7.1 顾客与喜好建模

- 顾客以**标签偏好**建模，例：`{三文鱼:+0.3, 芥末:-0.5, 价格敏感:高}`。
- 摆摊阶段顾客头顶显示**具体想要的寿司图标**（见 §5.4），教学友好。
- 玩家看到的是**间接线索/情报**，而非精确概率——预测的乐趣来自信息不完全。

### 7.2 地点系统：一组「旋钮」，逐步解锁

开摊前选择地点。地点用隐晦地名（如「XX 街道」），而非直白的「学校/写字楼」，需玩家自己摸清。每个地点是一组参数：

| 参数 | 说明 | 示例对比 |
|------|------|---------|
| 客群构成 | 决定喜好分布 | 学校街=学生为主 / 写字楼街=上班族白领 |
| 消费力 | 能否卖高价寿司 | 学校街低 / 写字楼街高 |
| 人流量 | 当日销量天花板 | 商业街大 / 写字楼街中但客单高 |
| 波动性 | 随机事件频率 | 学校街稳 / 商业街事件多 |
| **摊位租金** | 每日固定成本（风险闸门） | 学校街免费 / 写字楼街低 / 商业街高 |

**租金 = 风险闸门**：高租金地点每天先背固定成本，须「卖够本」才谈利润；与「浪费=实亏」（§5.5）叠成双重止损压力。地点选择由此从「选哪个好」变成「我扛不扛得住」：

```
学校街    免费    消费低、需求窄     → 保底点：稳、赚得慢、永远回得去
写字楼街  低租金  客单价高、需求偏高档 → 进阶，要先回本
商业街    高租金  人流大、喜好不集中  → 高风险高回报，需全套升级才接得住
```

- 地点**逐步解锁**（随进程/资金），教学更平滑。
- **学校街 = 保底点（安全网）**：几乎无成本、需求窄、玩家最早接触且很快摸清；即使有突发事件也在可承受范围，好感有地板（见 §7.3）不会没人来 → 无论玩多烂都能回来喘息。这是单机「永远有活路」的保证。
- **商业街 = 升级度考验**：喜好不集中 → 须**同时备多品类**才接得住 → 逼玩家先攒出**大冰箱**(带多种主料) + **大货架**(摆多种成品) + **大电饭煲**(走量)。地点解锁与装备成长线由此焊在一起。
- 进阶曲线：`学校街(保底·窄需求·易学) → 写字楼(高客单·偏高档) → 商业街(宽需求·大流量·需全套升级)`。

### 7.3 好感度机制（满足度驱动 + 情报奖励）

- **度量 = 0~100% 的比例值**（已确认）：好感度是**比例值**而非可无限累加的绝对数，**封顶 100%**；越接近上限涨得越慢（边际递减）→ 无脑刷只能摸到天花板，从根上杜绝数值溢出。
- **升降规则**：顾客**买到**喜好寿司 → 好感度↑；顾客**没找到**想要的（流失）→ 好感度↓。好感度因此成为对经营水平的直接反馈，紧扣核心循环。
- **好感度的两层回报**：
  1. **更多客人**：好感度越高，该地点人流越旺（开店阶段则表现为**回头客**更多，见 §6.6）。
  2. **更多情报（确定性）**：好感度解锁对这条街的认知，见 §7.4。
- **防恶性螺旋**（保证可恢复）：
  - 好感有**下限地板**，不会一夜跌回陌生；
  - **升快降慢**，单日翻车不清零；
  - **离开衰减**（已确认）：换地点后原地点好感**缓慢下降**，逼玩家权衡深耕 vs 探索。
- 由此形成经典张力：**深耕**（守一个点，好感复利、越来越好预测）vs **探索**（换新点，好感归零、需求陌生，但潜力更高）。
- **好感跌到「讨厌」→ 场景永久废掉**：某地点好感触底为「讨厌」时，**不再有任何客人**，该摆摊场景在**当前存档内永久失效**（比破产更痛——破产可重开，废点回不来），仅**重开新存档**才重置。
- **难度联动（好感地板受难度调节）**：
  - **普通**：所有地点都有地板，不会没人来，「讨厌/废点」不会发生。
  - **高难度**：**进阶地点**好感可跌为负 → 「讨厌」→ 场景永久废掉；但**保底点（学校街）保留地板**，安全网仍在。
  - **最高难度（硬核）**：**无保底**，连学校街也能跌到「讨厌」被废掉 → 可能被逼到只能重开。仅面向硬核玩家。

### 7.4 情报：好感逐步揭示「可学习的规律」

信息以「从顾客处收集情报」的形式随好感分层解锁，把抽象数值包装成叙事：

```
好感 0   → 只显示街道名(XX街) + 模糊印象
好感 ↑   → 人流规律情报：「这一带写字楼多，午市晚市人最多」
好感 ↑↑  → 喜好分布情报：「附近客人偏爱三文鱼」
```

- 目的：让玩家靠「常来 + 听客人说」慢慢摸透一条街，产生「我掌握规律了」的成就感，而非阅读数字表。
- **呈现载体 = 流言系统（见 §7.7）**：以上情报不做成数字面板，而由 NPC 搞怪台词说出。

### 7.5 随机事件（两类）

事件统一表达为「**临时改写当天的地点参数**」（改客群构成 / 改某食材忌口 / 改人流），与地点系统共用一套数据，便于扩展。

- **可预报事件（长期，摆摊教学期为主）**：开摊前给预告/线索（「明日情报」面板）。例：明天学校开放日 → 来很多大人 → 客群与喜好改变 → 玩家据此调整采购（多带高档料）。这是**技巧**，奖励会读预报的人。
- **临时随机事件（短期，中后期加重）**：当天触发、无预告。例：突发食安新闻，今日没人吃生鱼。这是**风险**，惩罚闭眼梭哈；早期少用，回转寿司阶段起加重。
- **正向客流事件**：由**热度**驱动的「购物狂潮」是主要的正向客流爆发点，统一在 §7.6 定义（热度与好感度分开，见 `00-术语表.md`）。

### 7.6 热度系统（独立于好感度）

> 热度与好感度是**两套独立指标**：好感度衡量「做得好不好」，热度衡量「有多少人气 / 客流」。二者互不换算。

- **累积来源**：① 顾客每**完成一次购买** → 热度小幅↑；② **举办活动**（发传单、投放广告等，需花钱）→ 热度较大幅↑。热度取值 `0~100%`。
- **购物狂潮（满热度爆发）**：热度达到 **100%** 时触发「购物狂潮」——短时间内**大量增加到店客人**，是把「攒人气」变现的正反馈爆发点；同时考验产能与备货。
- **与好感度的分工**：好感度高 → 回头客多、情报多（长期经营质量）；热度高 → 瞬时客流大（短期爆发）。两条线各自运营、可叠加收益，玩家既要「做得好」也要「有人气」。
- ❓待定：热度的**衰减规则**（不办活动时是否随回合回落）、各类活动的**成本与 +热度幅度**、购物狂潮的**客流倍率与持续时长**。

### 7.7 流言系统（情报 + 事件预告的统一「出口」）

> 灵感参考《主题医院》广播：同一渠道里有废话笑点，也有真情报，玩家得自己听。语气搞怪、略无厘头，是白盒阶段就能低成本注入「世界性格」的内容。

- **定位**：流言是 §7.4 情报与 §7.5 事件预告的**呈现载体**——不再单做干巴巴的数字面板，规律与预告都由 NPC 的俏皮话说出来。信息即氛围。
- **三类流言**：

  ```
  氛围型(纯搞怪)  「保安大叔：这一带写字楼真多啊，一到饭点全是白领」   → 世界性格
  情报型(真干货)  「老顾客：我们公司最近都流行吃三文鱼」             → =§7.4 喜好/人流分布
  预告型(看事件)  「隔壁摊主：听说下周学校要开放日，来一堆大人哦」    → =§7.5 可预报事件
  ```

- **解锁条件**：随**好感增加**与**摆摊事件**逐步涌现更多流言（好感越高，情报型/预告型越多、越准）。
- **两级可信度**（默认采用；可选「教学期全可信」）：
  - **确认情报**（好感解锁）：**永远可信**，是守点摸透这条街的真回报，不可被欺骗。
  - **小道消息 / 传闻**：**概率性**，可能真、可能夸大/过期/瞎传（「听说最近没人爱吃芥末了？」）——玩家自行判断押不押。高难度下**假流言更多**，考验分辨「规律 vs 噪声」，扣住「信息不完全下预测」的核心。
  - **摆摊教学期：流言全可信**（已确认）——教学期不出假流言，让新手先建立「听流言→摸规律」的信任；假流言（小道消息）留到**传送带阶段**才引入，作为新的风险层。
- **呈现方式**：
  - 决策阶段（开摊前）：一块「街坊流言板 / 今日传闻」集中阅读，辅助采购决策。
  - 营业中：NPC 头顶偶尔冒气泡台词，即时氛围 + 偶尔漏点情报。
- **说话人**（赋予世界角色）：保安大叔、老顾客、隔壁摊主、收音机、路人等；说话人可与内容类型挂钩。
- **制作建议**：白盒阶段就先攒一批搞怪文案（占位亦可），成本极低却能立刻让「数值游戏」有灵魂——是像素白盒期少数值得提前做的「美术级」内容。

### 7.8 待调数值 ❓

- 各地点的客群构成 / 消费力 / 人流量 / 波动性 / 租金。
- 好感升降速率、下限地板、离开衰减速率、各级情报解锁阈值。
- 各喜好标签的数值区间与「是否购买」的结算公式。
- 各事件的触发概率、影响幅度、预报提前量。
- 流言：各类流言触发频率、假流言比例（随难度）、文案库规模。

## 9. 经济 · 破产 · 难度（草案，需数值验证）

### 9.1 摆摊阶段经济

- 客单价约 1 元，靠走量；毛利极薄 → 强化「少浪费」的重要性。
- **初期食材无保质期**：食材囤着不做**不亏**，还可**跨天保留**到明天使用。保质期作为**传送带阶段**才解锁的新约束层（届时采购端才开始有风险）——具体机制见 §6.2、§6.3。
- 由此早期唯一亏损闸门 = **做成寿司却卖不掉**（实亏）；这把新手关的教学聚焦到「别过量生产」一课。
- 亏损来源（随阶段递增）：过量生产作废 →（后期）食材过期、租金。

### 9.2 破产与重开

- **破产判定**：现金 < 0，或「现金不足以采购任何食材 **且** 无库存可用」（彻底开不了张）。
- 破产 → 游戏结束；**单机可直接重开**，惩罚轻，鼓励试错。
- 触发前提：因有免费保底点 + 食材不亏，破产基本只发生在玩家**反复做最贵的寿司又卖不掉、耗尽本金**的主动失败。

### 9.3 难度设计

- **好感地板 / 废点风险**随难度递增（见 §7.3）：
  - 普通：全地点有地板，不会废点。
  - 高难度：进阶地点可跌到「讨厌」→ 场景永久废掉；保底点仍有地板。
  - 最高难度（硬核）：无保底，连学校街也能被废，可能被逼重开。
- ❓待定：其他难度旋钮（事件频率/强度、租金倍率、需求噪声幅度、初始资金）。

### 9.4 待定数值 ❓

- 各阶段的成本/售价/租金曲线、破产现金阈值。
- 保质期的引入时点与各食材保质天数（传送带阶段起）。
