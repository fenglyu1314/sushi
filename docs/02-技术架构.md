# 技术架构

> 引擎：Godot 4.7.1 ｜ 风格：2D 像素 ｜ 版本管理：GitHub ｜ 开发模式：单人 + AI 辅助，白盒优先。
> 标记 🔴待定 的为未拍板决策。

---

## 1. 引擎与语言

- **引擎**：Godot 4.7.1，2D 像素风。
- **语言**：✅ GDScript。
  - 理由：本项目为 2D 像素经营模拟，逻辑密集但代码规模不大，核心是频繁改规则/数值验证"好不好玩"。GDScript 迭代即时生效、AI 辅助生成质量高、与 Godot Resource 数据驱动无缝衔接，工具链最短。
  - 后期如有性能瓶颈或重构需求，再评估迁移 C#。

## 2. 数据驱动设计（核心原则）

内容（食材、配方、顾客类型、随机事件）全部做成**数据资源**，逻辑与数据分离，做到"加内容不改代码"。

- **方案**：以 Godot `Resource`（.tres）为主，编辑器内可视化编辑，GDScript 原生支持。
  - 注：`.tres` 文件不直接由 AI 创建/修改（见 `AGENT.md` §3.1）；加内容时由 AI 提供数据结构定义与内容清单，用户在编辑器内创建 Resource。

示例数据结构（概念）：
```
Ingredient  { id, 名称, 基础价格, 保质期(天/tick), 图标 }
Recipe      { id, 名称, 所需食材[], 制作耗时, 售价 }
CustomerType{ id, 喜好标签{}, 忌口标签{}, 价格敏感度, 出现权重 }
GameEvent   { id, 触发条件, 效果(改价/忌口/…), 持续时间 }
```

## 3. 时间 / 模拟模型（技术地基）

采用 **"一天为一局 + 内部 tick 推进"** 的双阶段结构，可同时支撑摆摊/传送带/座位：

```
┌─ 决策阶段(暂停) ─┐        ┌─ 模拟阶段(按tick推进) ─┐        ┌─ 结算 ─┐
│ 采购/备货/排菜单  │  ───▶  │ 顾客到达·传送带流转     │  ───▶  │ 收支   │
│                  │        │ ·消费/浪费实时计算       │        │ 复盘   │
└──────────────────┘        └────────────────────────┘        └────────┘
        ▲                                                          │
        └───────────────────── 进入下一天 ◀────────────────────────┘
```

- 模拟阶段用固定步长 tick 驱动（不依赖帧率），便于加速/暂停/存档。

## 4. 架构与通信

- **事件总线 / 信号**：用全局单例(Autoload)做事件中枢，系统间通过信号解耦（如"食材过期""顾客离开""菜品作废"）。
- **系统分层**：数据层(Resource) → 模拟层(纯逻辑) → 表现层(节点/UI)。模拟层尽量不依赖节点树，便于测试。

## 5. 建议目录结构

```
res://
├─ scenes/        场景(.tscn) — 在编辑器内创建
├─ scripts/
│  ├─ core/       时间/经济/存档/事件总线
│  ├─ systems/    食材·配方·顾客·传送带·布局等系统逻辑
│  ├─ entities/   寿司·顾客·厨师·服务员等
│  └─ ui/         界面脚本
├─ data/          食材/配方/顾客/事件 数据资源(.tres)
├─ assets/
│  ├─ whitebox/   白盒占位美术(色块/简图)
│  └─ art/        正式美术(后续替换)
docs/             设计与技术文档
openspec/         规范驱动工作流
```
> 注：`.tscn`/`.tres`/`project.godot` 等引擎文件请在 Godot 编辑器内创建/修改，避免绕过引擎的导入与 UID 管理。

## 6. 白盒美术约定

- 用纯色矩形/圆形 + 文字标签表示实体（如不同颜色代表不同寿司/食材/顾客）。
- 固定网格尺寸（如 16×16 或 32×32 像素）便于后续替换正式像素美术。
- 保持"占位可读性"：一眼能看出这是什么，而非最终观感。

## 7. 存档

- 序列化：现金、库存、进度、布局、当前阶段等。
- 建议用 Godot 资源序列化或 JSON 存档；模拟层数据结构应可纯数据化，方便存取。

## 8. Git / GitHub 约定

- **.gitignore**（Godot 4）：忽略 `.godot/`、`*.tmp`、导出产物等；保留 `.import`/`*.tres` 的处理按 Godot 官方模板。
- **分支**：`master` 稳定，功能用 `feature/*` 分支；配合 OpenSpec 每个变更一个分支更清晰。
- **提交**：建议约定式提交（feat/fix/docs/refactor…）。
